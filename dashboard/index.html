Isolation Forest, in plain language

The model isolates unusual log lines by randomly partitioning features. Lines that isolate quickly receive a higher score. Labels are not used to compute the score; they are used only to train on normal blocks, choose a validation threshold, and report held-out metrics.

Why recall stays low on HDFS-2k

This sample is almost one line per block, so the model has little sequence context. On the committed 399-block test split the official result is 1 true positive out of 13 actual test anomalies. That is a dataset limitation. The 0.35% corpus detection rate is a different statistic.

How to read this comparison

Held-out F1 is effectively tied (absolute delta under 0.005). That is not a proven overall improvement.

Baseline PR-AUC is substantially higher, so the baseline ranks test anomalies better.

The improved configuration reuses Isolation Forest settings selected on HDFS-2k. A full-corpus hyperparameter grid search has not been conducted.

Only held-out test metrics are shown here. Validation was used to pick the threshold and is not mixed into these scores.

train_on=normal · n_estimators=200 · max_samples=auto · threshold=0.129092 · rows=11,175,629 · loaded 11/17/2026, 2:23:00 PM

  • HDFS_v1 parquet rows have no official Drain EventId; EventId is a masked-content hash.
  • Lines that mention several blocks keep only the first BlockId, matching the 2k demo.
  • Block label is the max of the parquet "anomaly" flag (1 if any line in the block is labelled anomalous).
  • The 8-config Isolation Forest grid from HDFS_2k was not rerun on the full corpus.
  • Validation thresholds on large splits use score quantiles, not every unique score.
  • EventId one-hot width is capped at 64 values fit on train blocks only.
  • Isolation Forest is unsupervised; labels are not used as a supervised training target.
  • The live dashboard, /api/stats, /api/anomalies, and /api/retrain still serve HDFS_2k only.
  • A small held-out F1 delta is not a claim of improvement. Compare PR-AUC as well; the two can disagree.
  • Masked-content hashing can collapse official Drain templates into fewer EventIds.

System Blueprint · src/anomaly_pipeline.py

Leakage-Safe BlockId Isolation Forest Architecture

End-to-end data flow from raw HDFS structured logs to FastAPI & OMEN X.

STAGE 01

Ingestion & Join

Regex extracts first blk_-?\d+. Left-joins anomaly_label.csv on BlockId.

STAGE 02

Block Aggregation

17 features: lexical lengths, IPs, is_verify, has_exception, n_lines.

STAGE 03 (ANTI-LEAK)

60 / 20 / 20 Split

Stratified by BlockId. Frequency maps fit on Train blocks only.

STAGE 04

Isolation Forest

train_on=normal, 200 trees. Threshold 0.1824 tuned on Validation.

STAGE 05

FastAPI & UI

Serves /api/stats, /api/anomalies, and /api/retrain.

Why BlockId Splitting Matters

In HDFS, ground-truth labels apply to entire block sessions. Splitting randomly by line leaks lines from the same block across train and test sets. Splitting by unique BlockId guarantees zero overlap.

Why Recall Scales from 7.7% (2k) to 57.4% (11.1M)

HDFS-2k is a sparse sample averaging 1.003 lines per block. On the full 11.17M-line HDFS_v1 dataset, blocks contain multi-event traces, enabling Recall to jump to 57.36%.
